# Security boundary — local stage 1

Credentials: Argon2id (19 MiB, t=2, p=1), following [OWASP password storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Passwords 12–128 characters on registration/reset, no silent truncation. Unknown login still performs hash verification against a dummy hash. API bodies are limited to 16KB and strict Zod schemas reject extra fields.

Session: 32 cryptographically random bytes; only SHA-256 hash in PostgreSQL. HttpOnly, SameSite=Lax, Path=/, 7-day fixed expiry. Production uses __Host- prefix and Secure. Login rotates the current session, logout deletes it, reset deletes all user sessions. Tokens expire and are consumed atomically. Email verification is required by every ranked queue; guest/bot play is unrated.

CSRF: write methods require an exact allowed Origin, custom header and application/json. No wildcard CORS or permissive OPTIONS handler. Vite same-origin proxy preserves the browser's Origin. See [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). LAN origins must be explicitly added. Production requires HTTPS origins and authenticated SMTP, forbids default DB credential and local mail delivery.

Rate limits: 10/min/IP auth, 120/min/IP general; trustProxy=false avoids trusting forged forwarded headers. Behind a deployment proxy, explicitly trust only the proven proxy chain; never blindly set true. Distributed/account-aware credential limits and durable enforcement are still a production gate. Forgot-password response is generic, but SMTP timing equalization is not guaranteed in this local foundation. Deliveries are rate-limited per IP; per-account cooldown is a future hardening item.

Helmet applies CSP/nosniff/frame restrictions to backend responses. The frontend includes a Cloudflare Pages _headers template; same-origin proxy/CSP deployment must still be verified at the chosen host. It does not inherit API headers. React escapes text; no dangerouslySetInnerHTML. Database queries are parameterized. Error JSON omits SQL/internal stacks. Logger omits bodies, redacts Cookie/Authorization/Set-Cookie, strips URL query strings; email delivery errors omit token/recipient. Mail tokens are in URL fragments, sent only as JSON bodies. The local outbox contains sensitive single-use links and is excluded from version control. Do not expose it through HTTP.

Profile privacy, password changes and deletion are implemented; sensitive operations require current credentials, row locks and session revocation. Match actions authenticate and authorize HTTP/WS actors, validate Origin, enforce CAS and persist results before broadcasts.

Production release gates remain: physical-device/accessibility audits, linked-account abuse detection, SMTP, backups/retention, frontend production headers and prepublication license/secret review. No cloud resource exists. An npm audit is not a full security audit.

Current iteration: shared-browser account hashes suppress mutual XP/rating, without using shared IP as proof of abuse. This is a limited signal, not comprehensive anti-cheat. The proxy allowlist is configurable via validated IP/CIDR entries, default empty; never set blind trustProxy=true. Production database SSL verifies certificate/hostname; optional provider CA via DATABASE_SSL_CA_FILE. Gitleaks scans only staged publication files copied into an ignored clean folder, then Git history, so local outbox and runtime tokens are never published.
