# Playboard

[English](README.md) · [Українська](README.uk.md)

[![Перевірки](https://github.com/andrew-berezovskyi/playboard/actions/workflows/check.yml/badge.svg)](https://github.com/andrew-berezovskyi/playboard/actions/workflows/check.yml)

Адаптивна платформа стратегічних ігор: **шахи**, **шашки-64** та **Wayline** — власна тактична гра з картками руху. Реальний сервер Node.js і PostgreSQL, український та англійський інтерфейси, локальний шрифт Fixel, мінімалістичні темна й світла теми.

**Стан: працездатна локальна beta. Публічного сайту ще немає.** Посилання додамо після розгортання. Незавершені вимоги наведено нижче; повна відповідність турнірним правилам FIDE/IDF не заявлена.

## Можливості

- Три незалежні рушії з серверною перевіркою ходів, три рівні ботів у workers, приватні запрошення, пошук реального суперника, рейтингові/нерейтингові партії та серверні таймери.
- Перепідключення, збереження стану, реванш за згодою обох, історія й перегляд партій, PGN/FEN для шахів та JSON для інших ігор.
- Автоматичний гість, реєстрація, підтвердження пошти/відновлення пароля, Argon2id, HttpOnly-сесії, редагування й приватність профілю, видалення акаунта. Гостьові кімнати переходять у новий акаунт під час реєстрації.
- 24 інтерактивні задачі в трьох послідовних курсах, пояснення, збереження прогресу, щоденні завдання та навчальні партії з ботом. Підказки допустимих ходів не доступні у змагальних партіях.
- Окремі рейтинги Glicko-2 та їх історія; XP, рівні, місячні ліги, серії з урахуванням часового поясу, календар активності й досягнення.
- Друзі, блокування, онлайн-статус за згодою, запрошення, сповіщення й історія спільних матчів.
- Grid/Flex і явні медіазапити, дотик/перетягування/клавіатура, оформлення дощок і фігур, сітка карток, ефекти взяття, звуки та зменшення руху.
- Зв’язування акаунтів зі спільним браузером і ліміт винагород однієї пари. Це обмежує накрутку, але не виявляє всі мультиакаунти чи використання сторонніх рушіїв.

## Стек і структура

React 19, TypeScript, Vite, React Router, i18next; CSS Grid/Flex/media queries. Fastify, Socket.IO, Zod, Drizzle, PostgreSQL, Argon2id. Vitest, Playwright та axe.

- `apps/web` — сторінки, ігрові поля, переклади та стилі.
- `apps/server` — авторизація, матчі, боти, навчання, прогрес і міграції SQL.
- `packages/games` — незалежні правила, допустимі дії та відтворення партій.
- `packages/shared` — контракти, уроки/курси та Glicko-2.
- `scripts` — БД, міграції, локальний демоакаунт, backup/restore, обслуговування та перевірка секретів.
- `tests` — модульні, інтеграційні та браузерні перевірки.

## Локальний запуск на Windows

Встанови Node.js 24 LTS. У PowerShell:

```powershell
npm ci
Copy-Item .env.example .env
```

Обери один спосіб запуску БД: `docker compose up -d` із Docker Desktop або `npm run db:local` для embedded PostgreSQL. Термінал embedded-БД залиш відкритим. В іншому терміналі:

```powershell
npm run db:migrate
npm run db:seed  # необов’язковий локальний демоакаунт
npm run dev
```

Відкрий [localhost:5173](http://localhost:5173). API: порт 3001, PostgreSQL: 54329. Демоакаунт: `demo@plyvra.local` / `LocalDemoOnly!2026`. Seed працює лише локально та не запускається автоматично.

Листи за замовчуванням записуються в ігноровану папку `.local/mail`. Відкрий посилання підтвердження/reset із найновішого файла. Для Mailpit встанови `MAIL_TRANSPORT=smtp` і відкрий [localhost:8025](http://localhost:8025). Це локальна доставка, а не налаштована публічна пошта.

Змінні середовища описані в [.env.example](.env.example). `DATABASE_URL` використовується лише сервером. `WEB_ORIGIN` визначає посилання в листах, `ALLOWED_ORIGINS` — точний список дозволених адрес. Production потребує HTTPS, приватного підключення до БД та SMTP з авторизацією. Секрети не можна записувати у `VITE_*`.

### Мультиплеєр і телефон

Створи приватну кімнату та відкрий запрошення в іншому профілі браузера або інкогніто. Кожен профіль має окрему ігрову особу. Для телефона в тому самому Wi-Fi додай точну Network-адресу Vite в `ALLOWED_ORIGINS` і перезапусти API. Запити проходять через ПК, тому телефон не звертається до власного localhost. Дозволяй доступ лише в приватній мережі; не відкривай dev-порти в інтернет.

## Перевірки й обслуговування БД

```powershell
npm run check
npx playwright install chromium firefox webkit
npm run test:e2e
npm run licenses
npm run db:maintenance                 # лише показує кількість старих записів
npm run db:maintenance -- --apply       # видаляє прострочені тимчасові записи
```

Інтеграційні тести використовують окрему БД `plyvra_test`. Браузерні тести створюють локальні дані. Сценарії виконуються послідовно з паузами між групами, щоб дотримуватися обмежень частоти запитів.

Для резервних копій встанови сумісні PostgreSQL-клієнти. Якщо їх немає в PATH, вкажи папку bin у `PG_BIN`:

```powershell
npm run db:backup
npm run db:verify-backup
npm run db:restore -- --file=.local/backups/example.dump --confirm-overwrite
```

**Відновлення замінює вміст налаштованої БД.** Перевірка backup створює та прибирає власну ізольовану тестову базу. Дампи, паролі й листи ігноруються Git. Зберігай копії захищено та перевіряй відновлення перед публічним запуском.

`npm run build` створює `dist/web` і `dist/server`. Із `SERVE_WEB=true` команда `npm start` запускає інтерфейс, API та Socket.IO за однією адресою; без цього — лише API. [Інструкція Render](docs/DEPLOYMENT.md) описує Neon, пошту через HTTPS та квоти провайдерів.

## Перевірений стан і залишок

Точні результати наведені у [STATUS](docs/notes/STATUS.md) та [звіті ітерації](docs/notes/ITERATION_2026-10-11.md). Тести перевіряють правила, авторизацію, доступ, повторні дії, перепідключення, винагороди, курси й адаптивність. Емуляція браузера та автоматичний аудит не замінюють фізичні телефони й ручну перевірку.

Залишаються: довільні рідкісні шахові позиції без можливості мату поза реалізованими перевірками матеріалу/заблокованих пішаків; спеціальна негайна IDF-нічия (задокументований онлайн-варіант використовує лічильники ходів); тривале тестування балансу Wayline, комплексне виявлення зловживань, фізичні iPhone/Android і ручний аудит доступності. Публічна пошта, proxy/TLS, квоти сховища та розклад резервних копій перевірятимуться під час підготовки хостингу. Необов’язкові PWA, OAuth, чат і Stockfish не реалізовані.
